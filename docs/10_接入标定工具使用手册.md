# 10 接入标定工具（lanmai CLI）使用手册

> 由 DSH 起草 2026-09-21。这是 BP 里「部署路径」的**可执行版本**：把现场的运行数据接进来 → 体检 → 标定基线 → 输出分级告警。
> 代码：src/lanmai/（core.py 检测核心、pipeline.py 三段流程、cli.py 命令行）。零外部依赖（numpy/pandas 即可），不读 results/ 下任何中间产物。

## 一、它解决什么问题

污水厂要上新算法，最难的不是模型，而是**「我们厂的数据能不能直接用、基线怎么定、报警怎么分级」**。本工具把这三步固化成命令：

1. **inspect**：数据体检（采样间隔、缺失率、零方差通道、通道统计）——避免拿烂数据去建模；
2. **calibrate**：基线标定。按工况分层（运行状态列 / 一天中的时段 / 按负荷分位），给每个工况每个通道算冻结基线（median + 鲁棒尺度）与自适应窗参数，并把判据阈值定在参考窗分数的分位点上；
3. **watch**：输出**分级告警流**：P1（报警 + 分布位置抬升，立即处置）/ P2（仅报警，复核排计划）/ P3（仅分布位置抬升，趋势观察）。

**内嵌的五条设计原则**（都来自本项目实验，写进代码注释）：
① 双基线并行（自适应抓突变 / 冻结抓慢漂移）；② 工况条件化是刚需；③ 冻结参考域必须取稳态段（工具会做趋势体检并告警）；④ 慢漂移的严重度用分布位置比值表达；⑤ 阈值按工况自身基线，不用绝对值。

## 二、三条命令

    # 1) 体检
    python -m lanmai inspect --data 现场导出的.csv [--resample 1min]

    # 2) 标定（--state 可选 none / hour / col / quantile）
    python -m lanmai calibrate --data 健康期数据.csv --out baseline.json \
        --channels TP2,TP3,H1,Oil_temperature,Motor_current \
        --state col --state-col state --ref 0,0.23

    # 3) 分级告警
    python -m lanmai watch --data 待监测数据.csv --baseline baseline.json \
        --out alarms.csv --warmup 1D

    # 冒烟自检（合成阶跃 + 慢漂移，验证安装是否正常）
    python -m lanmai selftest

    # 多段健康期标定（推荐做法：见 §17.2 的教训——只用一段标定，阈值能差 2-4 倍）
    python -m lanmai calibrate --data 多段健康期.csv --out baseline.json \
        --channels TP2,TP3,H1,Oil_temperature,Motor_current --state col --state-col state \
        --ref-segments '0,0.08;0.09,0.17;0.26,0.34' --thr-policy median

（运行前把 src 加入路径：set PYTHONPATH=src 或 export PYTHONPATH=src）

**--ref-segments / --thr-policy（2026-09-21 新增）**：给多段健康期时逐段算分位阈值，再按策略汇总 —— median（折中，默认）或 upper（保守，压误报）；基线 JSON 里会同时写入每段阈值与「阈值范围（最小/中位/最大/极差比）」，方便在《设备健康基线报告》里说明"标定期选择对阈值的影响范围"。

## 三、在三个数据集上的实测（2026-09-21 实跑）

| 数据集 | 类型 | 规模 | 标定方式 | 结果 |
|---|---|---|---|---|
| SKAB（真实水泵台架） | 1 Hz，无故障记录 | 9,405 行 | 按小时分层，自适应窗 72 分钟 | 无故障记录 **3 个告警**（P2 2 / P3 1）；含故障记录 **1 个告警**（P2） |
| MetroPT-3（真实地铁空压机） | 1 分钟，306,960 行，带 state 工况列 | 214 天 | 按运行工况分层（stopped/unloaded/loaded） | **105 个告警**（P1 56 / P2 30 / P3 19），首报 2020-02-02 07:45 |
| BSM1（IWA 标准模型仿真） | 15 分钟，120 天 ×2 条 | 11,520 行 | 在**健康轨迹第 30-45 天**标定，按一天中的时段分层 | **6 个告警**（P1 3 / P3 3），**冻结通道首报 40.28 天** |

**最有说服力的一条**：BSM1 上 CLI 给出的冻结通道首报 **40.28 天**，与项目研究链路（src/dsh/dual_baseline.py）的结果**完全一致** —— 说明这个可搬运实现没有走样。

**多段标定的实测（MetroPT-3，三段健康期）**：阈值分别为 4.418 / 4.528 / 10.431 → **极差 2.36 倍**；取中位策略得 4.528。这与研究侧第 17.2 节的结论一致（换一段健康期，阈值能差 3.5-3.9 倍），也正是我们要求客户提供**多段健康期**而不是一段的原因。

**工具会自己提示参考窗不健康**：MetroPT-3 一跑就报
「参考窗内通道 Oil_temperature 有显著趋势（相对变化 0.97）→ 该段可能不是稳态，按设计原则③应更换参考窗」
（2–3 月油温本身在季节升温）。这正是我们要求客户做基线标定时必须配合的一件事。

产物目录：results/2026-09-21/lanmai_demo/（三个 baseline.json、四个 alarms.csv、cli_run_log.txt）。

在 BSM1 上实测（三段健康期、--thr-policy upper）：阈值被抬到保守值后，**单点事件机不再触发，只剩 5 条 P3（比值趋势）告警**；换成 median 策略则单点告警恢复（见 §18 系列：冻结通道首报 40.28 天）。这就是"保守策略换安静"的代价，材料里要如实写。

## 四、诚实边界（写材料时必须一起说）

1. **阈值必须按现场标定**：BSM1 那条之所以与我们的研究结论一致，是因为参考窗恰好取了稳态段；MetroPT-3 上本工具默认参数给出的告警数（105）与研究链路的冻结口径（205）不同，属正常——两者参考窗、阈值口径、工况划分不同。**现场部署必须先做标定期 + 并行观察期。**
2. **参考窗健康度无法自动判定**：工具只能告警「有显著趋势」，看不出「这段里有没有故障」，需要客户确认该段确无检修/故障。
3. **工况列质量决定上限**：MetroPT-3 的 state 是由 Motor_current/DV_eletric 推出来的；现场若没有可靠的状态列，只能用 hour 或负荷分位近似，效果会下降。
4. **分级规则是工程折中**：P1 用「报警 ∧ 分布位置比值 ≥ 1.15」；该阈值未做敏感性扫描（第 21 节里那套在线门禁实验说明了这类比值的取舍）。
5. 本工具是**检测-标定骨架**，不含诊断/剩余寿命；那两段在 src/dsh/ 的研究链路里。

## 五、现场接入最小数据集（给客户的清单）

- 时间列（任意格式，工具会识别）+ 6–12 个月历史；
- 每台关键设备 5–10 个过程量（温度、压力、电流、流量等）；
- **一个运行状态列**（如泵的启停/负载、鼓风机导叶开度档位）——没有的话用一天中的时段替代；
- 工单/检修记录（用于回标：判断我们的告警有没有价值）。

## 七、企业版离线报告（2026-09-22 新增，`lanmai report`）

**它解决什么**：把「一份现场数据 + 一份已标定基线」变成**可以直接发给设备科/厂长的报告** —— 体检摘要 / 标定摘要 / P1·P2·P3 分级告警明细 / 四张图 / 口径与局限 / 复现命令，全部渲染成**一个自包含 HTML**（图以 base64 内嵌），**离线双击即开，数据不出本机**。

```bash
python -m lanmai report --data 待监测数据.csv --baseline baseline.json --out report.html [--warmup 1D] [--resample 15min] [--max-alarms 40] [--no-fig]
```

**两份真实样例（已随仓库提交，可直接打开）**：

| 样例 | 数据 | 结果（与本文第三节实测完全一致） | 文件 |
|---|---|---|---|
| BSM1（IWA 标准模型仿真退化轨迹） | 11,520 行 / 9 通道 / 15 分钟 | **6 个告警（P1 3 / P2 0 / P3 3）**，冻结通道首报 1970-01-27 19:15 | demo/report_bsm1.html |
| MetroPT-3（真实地铁空压机 214 天） | 306,960 行 / 8 通道（含 state 状态列）/ 1 分钟 | **105 个告警（P1 56 / P2 30 / P3 19）** | demo/report_metropt3.html |

一键重生成：`python src/dsh/2026-09-22_10_lanmai_report_demo.py`（也挂在 run_all 的 lanmai_report 阶段）。

**报告里固定写明的局限**（与数字一起读）：① 阈值必须按现场标定（换参考窗可差 2–4 倍）；② 参考窗是否健康工具判不了，必须现场确认；③ 分级门限是工程折中；④ **本工具只做检测与标定**，不含诊断与 RUL；⑤ 工况列质量决定上限；⑥ 设备级退化要盯设备本体物料平衡量，且需多源冗余与漂移监控；⑦ 成本与收益不在报告内（占位值）。

**时间口径（v1.1 起，2026-09-22）**：真实现场数据（真实日期，如 MetroPT-3 的 2020-02 起）按日期展示；**仿真/相对时间数据**（时间列是数值、起点 0 → 会被 pandas 当 epoch 秒，显示成 1970 年）会自动切换为「**第 X 天**」：报告顶部给出显著说明，KPI、告警明细、标定参考窗与四张图的横轴全部改用相对天数（BSM1 样例的跨度 119.99 天）。这样仿真轨迹不会被误读成 1970 年的数据。

**本次顺手修掉的一个产品 bug**：`inspect` 遇到分类列（如 MetroPT-3 的 `state`）会因对字符串求均值而崩（2026-09-22 由报告生成器首次触发）；现已在 `pipeline.inspect` 中把非数值列单独列出（报缺失率与取值数，不参与均值/零方差判定）。

## 八、本地工作台（`lanmai serve`，方案 A，2026-09-22）

**一句话**：把 CLI 的三步搬到浏览器 —— 打开本机页面 → 上传「健康期数据」标定基线 → 上传「待监测数据」出报告。**纯 Python 标准库实现，零新依赖；默认只监听 127.0.0.1，数据不出本机。**

```bash
python -m lanmai serve                    # 默认 http://127.0.0.1:8765/；加 --open 自动开浏览器
python -m lanmai serve --port 8799 --out-dir lanmai_out    # 指定端口与产物目录
python -m lanmai serve --host 0.0.0.0                     # 局域网访问（会打印安全提醒，自行确认网络环境）
```

**页面四块**：

| 区块 | 做什么 | 产物 |
|---|---|---|
| ① 标定基线 | 上传健康期 CSV，选工况分层（hour / col / none / quantile）、参考段、多段健康期与阈值策略 | baseline.json（页面给下载链接；参考窗有趋势时会显著告警） |
| ② 出报告 | 上传待监测 CSV + baseline.json（可选重采样与预热期） | report.html（浏览器直接打开，即第六节企业版报告） |
| ③ 样例试跑 | 不用上传：BSM1（仿真，相对时间）与 MetroPT-3（真实空压机，105 个告警）各一个按钮 | 直接出对应报告 |
| ④ 产物列表 | 本机已生成产物（**只列产物，上传的原始数据单独放 upload/ 子目录、不在列表里**） | 可点击打开/下载 |

**安全默认**：只监听 127.0.0.1（本机）；上传上限 300MB；只接受 .csv/.csv.gz/.txt/.json；文件名只取 basename（防目录穿越）；无账号体系（内部工具定位）。

**一键冒烟（也挂在 run_all 的 lanmai_serve_smoke 阶段）**：`python src/dsh/2026-09-22_11_lanmai_serve_smoketest.py` —— 启服务 → 抓首页 → 样例出报告 → 上传数据+基线出报告 → 上传健康期数据标定 → 校验产物可打开 → 关服务；实测 6/6 通过。

**边界（务必一起说）**：① 它是**内部工具**，没有账号/权限/多租户；② 数据留在本机（刻意如此，符合工控网不出厂的习惯）；③ 与 CLI 完全同源（同一套 core/pipeline/report 函数），算法与阈值口径不因换界面而变化；④ 本工具仍只做**检测与标定**，诊断与 RUL 在另一条研究链路上。

## 九、Windows 快速上手（四种方式，任选其一）

> 注意：PowerShell 里 **没有 export**（那是 Linux/macOS 的写法），要用 `$env:PYTHONPATH`；并且要先 **cd 到仓库目录**。下面四种方式从最省事到最灵活：

| # | 做法 | 命令 / 操作 | 说明 |
|---|---|---|---|
| 1 | **双击启动器** | 双击仓库根目录的 `start_lanmai.cmd` | 自动 cd、设好路径、起服务并开浏览器；关窗口即停。最省事 |
| 2 | **一键入口脚本** | `python run_lanmai.py serve --open` | 不用设任何环境变量；脚本自己把 src/ 加进路径并切到仓库根 |
| 3 | **设置路径后运行** | PowerShell：`cd C:\Users\boyi\Desktop\BEWG_PdM` 然后 `$env:PYTHONPATH="src"` 然后 `python -m lanmai serve --open` | 等价于 CMD：`set PYTHONPATH=src` |
| 4 | **安装成命令行工具（可选）** | `python -m pip install -e . --no-build-isolation` → 之后任何目录都能 `python -m lanmai ...` 或直接 `lanmai ...` | 本机已验证可用；卸载 `python -m pip uninstall lanmai` |

**菜单与常用命令**（`serve` 页面上都有等价按钮）：

```bash
python -m lanmai serve --open                    # 本地工作台（推荐：上传 CSV → 标定 → 出报告）
python -m lanmai selftest                        # 冒烟自检（合成阶跃 + 慢漂移 + 回归检查）
python -m lanmai inspect   --data 现场.csv        # 数据体检
python -m lanmai calibrate --data 健康期.csv --out baseline.json --state hour --ref 0,0.3
python -m lanmai watch     --data 待监测.csv --baseline baseline.json --out alarms.csv --warmup 1D
python -m lanmai report    --data 待监测.csv --baseline baseline.json --out report.html --warmup 1D
```

**没有界面也能用**：`report` 生成的 `report.html` 就是企业版报告（自包含、可离线打开、可转发给设备科）。
