## 2. 覆盖率与分母口径（采纳 Codex 复核意见）
报告召回时分母必须写成"可评估事件"，并同时给出三个字段：
- raw_truth_events = 34（带故障文件数）
- evaluable_truth_events = 33（评估域内持续时间 ≥60 秒者）
- boundary_truncated_exclusions = 1（other/2.csv 原始区间 [104,488)，评估自 480 起，仅余 8 秒）

对外表述模板：
> 34 个带故障文件，其中 33 个事件满足冻结评估域内持续时间 ≥60 秒；另 1 个因评估起点裁剪后仅余 8 秒，不计入召回分母。

更换标定窗后必须重新报告这三个数，不得沿用 33。

## 3. 比对判据（采纳 Codex 复核意见，废除低计数 ±1 通道）
1. 真值事件分母、健康样本（时长）分母：**严格相等**。
2. 逐文件命中数、误报事件数、告警事件数等整数：**严格相等**；任一整数不一致即进入逐事件审计，不得用汇总相对差覆盖。
3. 连续量（TIA-H、误报率、延迟等）：在整数与分母严格一致之后，再用数值容差判断（相对 10%，浮点绝对容差 1e-9）。
4. 说明：v1.4 的收口是在**逐文件整数、分母、TIA-H 全部零偏差**下通过的，废除 ±1 通道不影响该结论。

## 5. 已知局限（对外必须一并说明）
1. SKAB 为人工注入故障、单台水泵台架，结论不能直接外推到污水厂整厂。
2. 故障注入点接近记录中点，标定窗与故障边界距离很近，存在乐观偏差；换数据集必须重测。
3. 目前所有方法都达不到"每 8 小时 ≤1 次误报"的运维预算，这是 P2 的主攻方向。
