# 01 项目速览（给项目负责人看的一页纸）

> 维护规则：本页只写「现在是什么、到哪了、还差什么」，细节一律指向其他文档。
> **最后更新：2026-09-22 晚**（技术侧已进入冻结待命）

## 一、一句话是什么
**澜脉（AquaPulse）= 污水厂设备的 AI 预测性维护系统**：不加新传感器，只用厂里本来就在记录的电流、温度、压力、流量等信号，回答四个问题 —— **有没有异常 → 是什么故障 → 还剩多久 → 什么时候修最省**。纯软件，报**创意转化组**，命题方向 **2-6「基于 AI 设备预测性维护与管理技术与解决方案」**（命题原文已核对）。

## 二、技术链四段（都在仓库里可复现）
| 环节 | 回答 | 关键数字（口径见 PROJECT_STATE） |
|---|---|---|
| ① 检测 | 有没有异常/退化 | 双基线（冻结管慢漂移 + 自适应管突变）+ 工况条件化 + 事件机 → 分级告警 P1/P2/P3；真实空压机 214 天 105 个告警（P1 56 / P2 30 / P3 19）；同召回下误报比对照实现少 2.8 倍 |
| ② 诊断 | 是什么故障 | CWRU 轴承：同记录 / 跨转速 宏F1 1.000；跨故障尺寸 0.536（边界已标注） |
| ③ RUL | 还剩多久 | C-MAPSS GBR RMSE 15.27 / PHM08 434；孪生机理 RUL 误差 1.00–4.04 天 |
| ④ 决策 | 何时修最省 | AI 相对最优固定周期：C-MAPSS 省约 16%（12/15 格）、污泥线脱水机省 24.5%（9/9 格）——**成本为占位值** |

## 三、四件能拿出去给人看的东西
1. **本地工作台**（方案 A）：双击 start_lanmai.cmd，或 python run_lanmai.py serve --open → 浏览器上传 CSV → 标定基线 → 出报告；
2. **企业版报告**（方案 B）：lanmai report 生成自包含单文件 HTML（体检 / 标定 / P1·P2·P3 告警 / 四图 / 局限 / 复现命令）；
3. **线上演示页**：落地页 index.html + 十节汇总看板 + 交互式数字孪生演示台 + 两份真实样例报告（GitHub Pages）；
4. **一键复现**：run_all.py（快速 9 阶段约 20 秒 / 全量 39 阶段）+ 四轮独立复核台账。

## 四、验证与证据（评分最看重的部分）
- **真实数据**：SKAB 真实水泵台架（三方法双实现零偏差、DET 曲线定稿）、MetroPT-3 真实地铁空压机（冻结口径已声明标签依赖性）；
- **机理仿真**：BSM1 标准模型闭环 + 工况 / 雨暴雨 + 双基线 + 多轨迹 + 在线因果门禁；**BSM2 整厂**（二沉池 120 态 + ADM1 消化罐）+ 污泥线脱水机闭环 + 两条补强；
- **跨实现复核**：批次 2 / 4 / 5 / 6 四轮独立复核（PROJECT_STATE 第 19 / 26 / 28 / 31 节），被指出的问题全部回写；
- **冻结前数字总检**：30/30 通过（数字 ↔ 结果文件 ↔ 文档三方对齐）。

## 五、必须一起说的三条边界（不许含糊）
1. **污水厂侧全部是机理仿真**（材料一律标「仿真」）；真实设备只有水泵台架与地铁空压机 → 上线必须走试点（POC），**不得宣称已在污水厂现场验证**；
2. **成本参数是占位值** → 「省 16% / 24.5%」**不得作为真实金额**对外；
3. **设备级退化**（如脱水机含固率下降）在沼气 / 能耗 / 出水水质上几乎不可见（第 27 节实测 ±0.03%）→ 只能靠设备本体物料平衡量（干固体 / 湿泥饼量）发现，且怕系统性标定漂移（须多源冗余 + 独立漂移监控）。
