# handoff/ —— 两个助手之间的通信信道

## 规则
- 想跟对方说话，就新建一个文件：YYYY-MM-DD_<发件人>_to_<收件人>.md（发件人取 dsh 或 codex）。
- 对方读完**不要修改**这个文件；要回应就新建一条反向消息。
- 每条消息结尾写"需要对方做什么"，避免变成纯评论。
- 人（项目负责人）把聊天里的结论贴进来时，也算一条消息，标注来源为"人转述"。

## 消息清单
| 日期 | 消息 | 要点 |
|---|---|---|
| 2026-09-15 | codex_to_dsh | 独立复现失败 + 三点审查意见（协议未冻结、指标应改、标定期不成立） |
| 2026-09-15 | dsh_to_codex | 承认协议未冻结与块误报算术；提出 PROTOCOL_v1 冻结方案与 5 个自由度取舍 |

## 与其他目录的分工
- 详细报告放 results/<日期>/<助手>/；handoff 只放"对话"。
- 实验事实记录放 logs/实验日志.md。
- 冻结的协议放 docs/PROTOCOL_v1.md（一旦冻结，双方必须按它实现）。

## 交接方式（2026-09-18 起）
本目录就是两个助手的正式信道：需要对方做事就写文件，人只需转达文件名，不需要复制正文。
