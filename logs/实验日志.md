### 2026-09-15 DSH SKAB 基线：传统报警值 vs 无监督模型
- 脚本：demo_pdm_v5.py / demo_dl.py / demo_changepoint.py
- 命令：python demo_pdm_v5.py（另两个同理）
- 数据：SKAB 真实水泵数据，35 个 CSV，1Hz×8 路信号
- 结果：
  - 固定报警值（工业常规）：事件检出 82.4%，误报分钟 19.7%，延迟 60s
  - PCA 重构误差（自适应基线）：检出 88.2%，误报分钟 15.9%
  - 马氏距离（自适应基线）：检出 100%，误报分钟 59.5% → 判为"一直在报"，失效
  - 1D 卷积自编码器：检出 23.5%（全局迁移）/ 17.6%（自校准）→ 小样本+漂移下翻车
  - 变点检测器：检出 61.8%，误报分钟 26.9%
  - 变点+PCA 融合：检出 91.2%，误报分钟 34.7%
- 结论：
  1. 单一模型必然偏科，多检测器融合能显著提检出。
  2. 真正的瓶颈是误报控制，不是检出。
  3. 自编码器在工业小样本+强漂移场景不适用（作为反面案例写进 BP）。
- 失败/存疑：前三版评估协议有误（F1 被 61% 的故障基数污染），已改为"误报分钟比例 + 事件检出率"；"误报事件次数/小时"这一指标因报警段合并失效，需重做。标定期假设"文件前 40% 正常"，对 other/2.csv 不成立。
- 下一步：拉 MetroPT-3 做真实故障验证；出 DET 曲线；C-MAPSS 做 RUL。

### 2026-09-15 Codex 独立复现 SKAB、体检 MetroPT-3、审查评估协议
- 脚本：src/codex/2026-09-15_01_skab_repro.py；src/codex/2026-09-15_02_metropt3_audit.py；src/codex/2026-09-15_03_review_dsh.py
- 命令：python src/codex/2026-09-15_01_skab_repro.py; python src/codex/2026-09-15_02_metropt3_audit.py; python src/codex/2026-09-15_03_review_dsh.py
- 数据：SKAB 34 个带标签故障 CSV（共 37,401 行，1Hz×8 路）；MetroPT-3 官方 UCI 791 ZIP 218,381,995 bytes，CSV 1,516,948 行×15 路传感器（只缓存到系统 TEMP，未改 data/）
- 结果：
  - SKAB 固定稳健 z：事件检出 44.1%（15/34），误报分钟 21.9%（30/137），延迟中位 0s；DSH 报告为 82.4% / 19.7% / 60s，未复现。
  - SKAB PCA：事件检出 79.4%（27/34），误报分钟 54.7%（75/137），延迟中位 0s；DSH 报告为 88.2% / 15.9% / 0s，未复现。
  - MetroPT-3：官方文件可读取，1,516,948 行，0 缺测、0 重复时间戳、0 无穷；实测中位采样间隔 10s（约 0.1Hz），与官方元数据/PDF 所写 1Hz 冲突；4 个公司报告空气泄漏窗口均在 CSV 内有覆盖。
- 结论：
  1. DSH 数字目前不是可独立复现的“统一协议”结果：固定报警是否自适应、滑窗特征、分钟聚合、事件命中窗口和误报分母未冻结；>30% 偏差主要出现在固定法检出和 PCA 误报。
  2. 误报分钟比例若定义为 FP/正常分钟不受故障基数直接稀释，但 F1/precision 会被高故障基数误导；核心指标应改为独立误报事件/健康运行小时 + 相同误报预算下的事件召回/延迟。
  3. MetroPT-3 可用于真实故障验证，但必须使用时间窗口、工况条件化、维修后 walk-forward 标定，不能原样套 SKAB 的点数窗口和文件前 40%。
- 失败/存疑：未复现 DSH 两个基线；没有读取 DSH 脚本，故不能定位其具体代码行，只能确认结果报告缺少足够协议定义。MetroPT-3 官方第二条故障记录编号重复为 #1，且维护日期“30 Apr”早于 5 月故障窗口，疑似原始文档笔误；保留存疑。官方宣称 1Hz 与实际约 0.1Hz 冲突。

### 2026-09-15 DSH PROTOCOL_v1 首跑（F0/F2/F3 + 事件化判决）

- 结果（事件化判决，阈值=标定期 0.995 分位）：

  - fixed 标定期：F0 14.7%/0.31/0.8%；F2 58.8%/9.85/26.1%；F3 100%/0/**88.3%**
- 结论：
  1. 事件召回与误报事件数单独使用会被'一直报警'刷分（F3 fixed：召回 100%、误报事件 0，但健康时间 88.3% 在报警）——必须与 TIA 成对使用。
